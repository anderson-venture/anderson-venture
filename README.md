## How I Build

- **Follow the conventions.** Conventions exist so the next developer knows where things live.
  Fight them only when there's a real reason.
- **Thin entry points, clear logic.** Validation, authorization, and business logic each have their
  own place — small, single-purpose units that are easy to test and reuse.
- **Types all the way down.** Let the compiler and static analysis catch what code review misses.
- **Design the contract first.** Define the API or schema before implementation — the contract is
  what the front end and other teams depend on.
- **Push slow work to the background.** Emails, webhooks, reports, and third-party calls belong in
  jobs with retries, not in the request cycle.
- **Test where it pays.** Feature tests for the happy and unhappy paths, unit tests for logic, and
  end-to-end tests for the flows that make money.
